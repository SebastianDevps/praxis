# Tier 3 smoke — the $3 that stopped an $18 run

**2026-08-29 · 10 cells · $3.00 · claude-sonnet-4-6 · 1 error**

A gate on one before spending on sixty. The plan was a 60-cell A/B on the Spanish routing gap; this
ran ten English best-case prompts first to check the instrument could see an activation at all.

Instrument: `evals/route/smoke.mjs`.

---

## Why this ran before the real eval

Two instruments already said the Spanish gap is real, and they disagree with something I asserted
while ratcheting the routing floor:

| instrument | says |
|---|---|
| `routing-audit` (lexical, free) | rank-1 EN 69.2% · **ES 23.5%** |
| [activation audit](2026-08-28-activation-audit.md) (961 real transcripts, free) | skills fired **3 times in 154**; names the English-description / Spanish-user mismatch as the cause |

The commit that split the floor by language claimed the gap was "a property of the proxy, not the
descriptions — the real router is an LLM and crosses languages fine." That was not verified, and
the activation audit in this same repo says the opposite on real behaviour. Two orthogonal
instruments agreeing outrank one unverified assertion.

So the paid question was never "is the gap real". It was **"does an intervention close it"** — and
that only pays if the eval can distinguish arms at all.

## Result 1 — the detector works, after one scorer bug

Skills are invoked as `praxis:test-coverage-plan`, not `test-coverage-plan`. The first scorer
compared bare names and reported **0/10 where the truth was 2/10**, printing the correct skill name
on the same line as the word "other".

Same class as the `BLOCK`-inside-a-negation bug in the refute scorer: a predicate that reads
plausibly and is wrong in one direction only. Found by reading the table rather than the number.
Rescoring the saved run cost nothing.

## Result 2 — what the ten cells actually did

| behaviour | cells |
|---|---|
| invoked the expected skill | **2** (`test-coverage-plan`, `strategy-compare`) |
| dispatched an agent | 2 (`frontend-design`, `scout`) |
| only inspected the workspace (Bash + Read) | 6 |
| session error | 1 |

Precision when a skill fired: **2/2.** Nothing fired the wrong skill.

The 2-skills-vs-2-agents split reproduces the activation audit's central finding independently and
prospectively: *the agent layer works, the skill layer barely fires.*

## Result 3 — the smoke has a confound, and it is mine

The workspace was deliberately bare — one `README.md` — so that a real repo could not steer the
routing. That also made six of the ten prompts unanswerable:

```
"Review this component and tell me what is wrong with it."
"Audit this login handler for OWASP issues."
"Before I add a rate limiter, is there anything like it already in this codebase?"
```

There is no component, no login handler, no codebase. **"No skill fired" and "the prompt had
nothing to act on" are indistinguishable in that setup.**

The tell is in the data: the only two cells that invoked a skill are the only two whose prompts need
no code to answer — `test-coverage-plan` ("what should we test for this new checkout flow?") and
`strategy-compare` ("cron job, queue, or durable object — compare them"). That is not a coincidence
about routing; it is a property of the fixture.

Which makes this the **same failure as the refute eval's "clean" task**, where a fixture that did
not satisfy its own contract made all six cells look wrong. Second time. The lesson did not
transfer because it was recorded as a finding about that fixture rather than as a rule about
fixtures.

## Verdict

**Do not launch the 60-cell language A/B.** Not because the gap is not real — two instruments say
it is — but because this smoke cannot yet tell a routing failure from an unanswerable prompt, and
an A/B built on it would inherit the confound at six times the cost.

**Seed a fixture the prompts can act on**, as `evals/refute` already does, then re-run these ten.
If the expected skill still fires 2/10 on answerable English prompts, the bottleneck is not Spanish
and the language A/B is the wrong experiment entirely.

## Cost, and a standing error

$3.00 for 10 cells — **$0.30/cell**. I estimated $0.05–0.15.

That is the third consecutive eval whose cost I underestimated (the refute matrix: estimated $10,
actual $31; the no-orchestrator rewrite: predicted 40–50% savings, measured +12% on one arm). The
60-cell run would have been ~$18, not the $3–9 I quoted.

Standing correction: **estimate eval cost from a measured cell, never from reasoning about prompt
length.** The smoke pattern already enforces this — it just has to be run first every time.

## Reproduce

```bash
node evals/route/smoke.mjs --dry-run   # free; prints the plan
node evals/route/smoke.mjs --run       # ~$3
```
