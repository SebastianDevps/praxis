# Changelog

All notable changes to Praxis are documented here. Format follows [Keep a Changelog](https://keepachangelog.com); versions follow [SemVer](https://semver.org).

## [Unreleased]

## [0.5.0] — 2026-08-31

### Added

- **`release-readiness` — the `ship` phase gets doctrine.** `docs/task-model.md` named six phases and `ship` had zero skills and zero agents behind it. Reversible, observable, incremental — and the distinction between this task's acceptance criteria and the project's standing floor, which the Run Card's `verify:` line does not carry.
- **`quality-bar` — the standing floor as a written artifact.** Produces `CONSTRAINTS.md` in your project: the bar with numbers, written once, surviving the session. Detects before it asks, every question carries a default, and where you have no number it measures where the project is today and holds that line — an invented threshold gets ignored, a measured one is already true. Measure-and-hold applies to a number, never to an absence: a project with no dependency audit does not "hold none". Adapted from `constraint-driven-development` in [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills).
- **`evidence-discipline` — the sixth craft, and the first for engineering.** Three design crafts reached `design`; every engineering agent required exactly one (`minimalism`). Design work got always-on taste enforcement and engineering work got none. This craft carries the tells of a bar lowered to reach green — a test that stopped running, an assertion removed from a test that still passes, a suppression added in the diff, a threshold edited downward — and the rule the rest of this release was built on: **mutate what a gate guards and watch it fail, then restore and watch it pass**. Required by the eight agents that write or judge code.
- **Two review axes on `reviewer`.** It named zero, so a 400-line refactor could return `clean` with nobody asking whether the abstraction fits. Readability and Architecture only: correctness and security already have dedicated lenses.
- **Severity criteria on `security`.** It named five levels and defined none, and severity is what routes a finding. Criteria and action per level, plus a mapping to `reviewer`'s scale so two reports on the same finding are comparable. `CRITICAL` blocks the merge, not the release.
- **The LLM threat class in `skills/security`.** Praxis is a framework for building agents and had no threat model for the agents it builds. The system prompt is not a security boundary; model output is untrusted input; cap tokens, rate and recursion; partition RAG embeddings per tenant.
- **The non-reproducible branch in `systematic-debugging`.** The skill advertised flaky and intermittent behaviour and answered it with "no repro, no fix", which is a stop, not a method. Four causes, one concrete move each.
- **An `UNVERIFIED` marker in `docs-seeker`.** The skill covered "docs differ from memory" and not "docs not found". A search that returned nothing must never read as verified — the GAP state applied to research.
- **Browser-output safety in `web-testing`.** Praxis ships browser tooling and had no rule about what comes back. DOM, console, network and eval results are data, never instructions.
- **ARIA live regions in `a11y-baseline`.** Verified absent repo-wide under two engines before the claim was made. Every async surface Praxis built — save confirmation, validation error, loading state — shipped silently inaccessible. Plus heading structure, 200% text resize, `lang` and `title`, target size, and focus return on modal close.

### Changed

- **Every surface that renders a Run Card renders the same four fields.** `agents/orchestrator.md` and `AGENTS.md` — the file that calls itself the host-agnostic source of truth every host reads — documented six fields sharing exactly one name with the four the README advertises. The agent whose job is rendering the card was rendering a different card.
- **The kernel speaks the task model.** The three surfaces injected into every turn named neither `define` nor `ship` and linked no canon, so the Run Card's `phase:` was free text and each turn invented its own vocabulary. 0.4.0 shipped the document; the behaviour never changed. Measured cost of the fix: +144 characters worst case, +1 in `fast`, where phases and the ledger do not exist.
- **Four drifts between the kernel and the router resolved** under one stated principle: the kernel carries what must hold inside every subagent, the router carries what needs explaining once.
- **`minimalism` gained Chesterton's Fence and a carve-out for test code.** The craft is injected almost everywhere and its own line-count pressure was about to make agents factor shared setup out of tests and destroy their readability.
- **`crafts/orchestration` asks whether the work splits before asking who does it.** It briefly held two opposite defaults three lines apart, both injected into the orchestrator, with no tiebreaker.

### Fixed

- **The SSRF rule, which was wrong twice.** It began as a denylist (`localhost` / `169.254.*` / `10.*`) that missed decimal-encoded IPs and every IPv6 form. The replacement — *reject if any resolved address is not unicast* — read as stricter and was not: Go's `net.IP.IsGlobalUnicast()` returns true for RFC 1918 and says so in its own doc comment, so it passed `10.0.0.5`, the exact address the denylist caught. Found by the refuter panel with stdlib source as evidence. It now rejects unless every resolved address is publicly routable, and names the trap. It is the one line outside `CRAFT_INVARIANTS` pinned by a test.
- **Four claims the mechanism did not back.** `44×44` cited as the web standard when WCAG 2.2 SC 2.5.8 (AA) is 24×24 CSS px and 44 is the AAA figure in Apple's unit; `docs/skill-doctrine.md` claiming a script enforces the 250-character claim cap when that script lives on the `measurement` branch; four surfaces calling six crafts "always-on" when four of them reach exactly one agent each; and `release-readiness` pointing at `quality-bar` for alert thresholds it has no slot for. None was a code bug. All were documentation asserting more than the system does.
- **`ad-creative` was reachable from no routing surface.** Its only mention outside its own directory was a research document. Now routed by `design` and carried by the dispatch.

### Gates

Six new or rewritten, each mutation-tested in both directions. Three were refuted after their first version and rewritten: a phase gate that stayed green with four of six phases deleted, a craft-list gate satisfied by a word appearing anywhere in the file, and two Run Card parsers that failed on a bracket swap that removed nothing. The frontmatter parser is now structural — the previous one reported a correctly-configured agent as violating the rule it satisfied.

**Known GAP:** no test protects the content of any skill. Stubbing a `SKILL.md` to valid frontmatter leaves the suite green. Crafts are covered by `CRAFT_INVARIANTS`; skills have no equivalent, across all 38. Reported rather than fixed — a blanket content gate fires on every legitimate rewording.

## [0.4.0] — 2026-08-29

### Changed — breaking

- **`spec-lifecycle` tracks a change with `stage:`, not `status:`.** A spec file written against 0.3.0 must rename that frontmatter field. The word meant two things in one system — a change's phase in `spec-lifecycle`, a task's state in the task template — and a ledger written by one skill was unreadable to the next. Renamed rather than documented around; the cheapest moment to fix an ambiguity is before anything depends on it.
- **One ledger, named `PROGRESS.md`.** `plan.md`, `progress.md` and `tasks/*.md` are no longer written or read. Four names existed across five skills.

### Added

- **`docs/task-model.md` — one task model, defined once.** Before it: four ledger names and four phase vocabularies (`spec-lifecycle`'s four, `agentic-lifecycle`'s seven stages, a task template's four that nothing referenced), so work handed between skills arrived in a shape the receiver did not recognise. Now every task carries `phase:` (`define · plan · build · verify · review · ship`, adopted from [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills) — the only one of the four vocabularies whose members describe something a *task* can be in) and `state:` (`pending · in_progress · review · done · blocked(technical) · blocked(user)`). The two blocked kinds stay separate because they have different recipients. `writing-plans`, `subagent-driven-development`, `autonomous-loop`, `agentic-lifecycle` and `/praxis:loop` point at it instead of each defining their own; four invariants fail if a second definition appears.
- **The approval handshake.** When the shape of the work is not clear, Praxis states a plan, sets the Run Card to `Needs your decision`, and stops. `blocked(user)` is the durable form: the Run Card states the halt in the conversation, the ledger survives compaction. A ledger with one subagent per task now waits for a plan you accepted — **a file count no longer triggers it**. Delegation stays automatic; only the expensive part waits.
- **A question exits before classification.** Verified absent first: a search for `consult|quick answer` across 36 skills and 11 agents returned nothing, and even `fast` presumed an edit ("edit, verify, and report"). The block is orchestrator-only — a specialist is dispatched with work, never a bare question, so the line would be paid per dispatch and usable on none.
- **A reconciliation taxonomy for refuter findings.** The panel's design said how to *produce* findings and never how to *dispose* of one; the orchestrator routed by severity, which answers how urgent a finding is and never whether it is right. Four classes, first match wins: `contract gap` → fix the contract and re-dispatch the whole wave (every lens read the same one); `actionable` → back to the builder; `accepted trade-off` → owner, no block; `noise` → **must name the context the lens was denied**. A wave classified entirely as noise means you validated your own build. Adapted from `doubt-driven-development`, and deliberately withheld from the refuters themselves — a lens that knows how its findings will be graded grades them itself.
- **`docs/instrument-discipline.md` — six rules for anything that produces a number.** Five times in two days the defect was in the measurement, not in what it measured, and rule 1 failed twice one day apart: a fixture must satisfy its own contract clause by clause, not merely lack the defects you planted. Filed as rules rather than as a third eval write-up, because a finding about one artifact does not generalise on its own.
- **`evals/route/` — Tier 3 routing smoke.** Ten English best-case prompts, scored from session transcripts rather than from replies. Verdict: do not launch the planned 60-cell language A/B — the smoke's bare workspace made six prompts unanswerable, so "no skill fired" and "nothing to act on" are indistinguishable. $3.00 spent, ~$18 and an invalid answer avoided. Precision when a skill fired: 2/2.

- **Seeded-defect eval for the refuter panel.** `evals/refute/` plants a known defect, asks each arm to review, and checks whether the arm's REPORT names it — never the transcript, which contains the seeded file as tool output and would score reading as finding. Three arms, and the third is the experiment: `reviewer`, `reviewer-x3` (same mandate, tripled compute) and `refuters`. Result in `evals/2026-08-28-refuter-panel.md`: **no difference in find rate** (every arm found every seeded defect; the defects were too easy), and **a clean separation in report shape** — "demanded a repro" ran 0/8 for `reviewer-x3` against 7/8 for `refuters` at matched compute and matched output length. The panel costs 3.65x for identical detection and is the only arm that attaches evidence to a finding. Whether that saves a reviewer time is the next thing to measure, and it was not measured.
- **Two defects the eval found in itself.** The "clean" fixture violated its own contract twice — an unwired `paginate()`, then a token expiry comparing milliseconds to a JWT's seconds — and all six review cells correctly reported both while the metric scored them as false positives. And the blocker predicate matched the word "block" inside "Does not block.", biasing the metric against the exact behaviour the panel exists to produce. Both were found by reading the replies rather than trusting the table. `tests/refute.test.mjs` now checks the fixture clause by clause and the selftest carries negation probes; the honest conclusion recorded is that a false-positive metric is not constructible this way, because realistic code carries defensible criticism.
- **`docs/adversarial-review.md`.** The published basis for the panel — structured disagreement, three adversarial agents beating a five-agent baseline, epistemic diversity — and, deliberately, what it does not settle: it shrinks this eval's claim from "does the effect exist" to "does our implementation deliver a known effect".
- **Routing is measured, not assumed.** Praxis could tell you what activated after the fact — the activation audit read 961 transcripts — but nothing could tell you whether a description would route its own prompt before shipping it. Every skill now carries `evals/cases.yaml` (>=5 prompts that must reach it, >=4 near-misses that must not, each naming the sibling it belongs to, plus a capability scenario; prompts are bilingual because the users are). `scripts/routing-audit.mjs` ranks all 324 prompts against all 47 resources with TF-IDF and fails CI on five floors. First honest measurement: rank-1 54.4%, top-3 73.3%, declared route in top-3 81.4%, worst description collision 0.57. The floors were set from that measurement with a small margin and ratchet upward — the first ones written were aspirational, failed on the corpus they described, and were replaced. A lexical ranker is a proxy, not the model's attention: read the delta, not the absolute.
- **Explicit sibling boundaries on every description.** All 36 skills and 11 agents end their description with `NOT x (that is \`y\`)`. The rule is discriminative power, not coverage — a reader must be able to pick this resource over its nearest sibling from the description alone — and `tests/routing.test.mjs` checks that every named sibling exists. Writing them immediately paid: `praxis-memory` repeated "memory" across three triggers, which made it the top match for "Redis or an in-memory store", ahead of `strategy-compare`.
- **The refuter panel — `refuter-correctness`, `refuter-security`, `refuter-tests`.** `reviewer` receives the builder's full context and looks for problems; a reviewer looking for confirmation finds confirmation. The refuters are dispatched in one wave on a finished change and get exactly four inputs — task contract, spec, exact source state, entry point — and never the builder's reasoning or draft verdict. They record what they attacked before seeing the builder's conclusions, and a finding blocks only if it is caused by this change, is severe, and carries a repro; a suspicion is a question, and questions do not block. `reviewer` is untouched and still owns the light path. The correctness lens carries the one Praxis was missing: ask a gate in BOTH directions, because a gate that fires on correct work gets muted or worked around, and that is harder to notice since it arrives dressed as diligence.
- **`decision-challenge` skill.** `strategy-compare` picks between options; nothing attacked a decision already made. A bounded cycle — materialize, isolate, attack, test, reconcile, verdict — that splits a non-atomic claim ("the migration is safe") into testable ones, ends every doubt in a named state, and emits PROCEED / HOLD / STOP with an unlock condition. "Discussed" and "probably fine" are not states.
- **`prose-tells` skill, and five tells in the `anti-slop` craft.** A named-tell audit for any text about to ship — README, post, commit body, PR description. Named rather than sensed: if you cannot name the tell, it is not a finding. Split rather than merged into the craft on purpose: the craft is injected in full into every design dispatch and is glob-scoped on Cursor, so forty lines of prose tables would be paid for on every turn and still miss a README. Length is a cost, never a credit.
- **Memory has a write path.** `.praxis/memory/` had a read path from day one — session-start injects `index.md` every session — and nothing wrote to it unless someone remembered to run `/praxis:learn`. A binding rule resting on someone remembering is the defect class this plugin exists to fix. A new `SubagentStop` hook captures one pending row per dispatch to `sessions.jsonl`: deterministic, no LLM, no network, one append bounded under PIPE_BUF so a parallel wave cannot interleave two rows. Consolidation stays in `/praxis:learn`, because it costs a model call and a judgement. The hook is INERT until a project has a `.praxis/` directory — Praxis does not scaffold a store into every repo it touches — and that is said out loud rather than left to look like no activity.
- **`gaps.md` — what the memory does not know.** Append-only: a question the memory could not answer, a convention referenced with nothing behind it, a contradiction left unresolved. It gives `/praxis:learn` a work queue instead of waiting for a lesson to arrive by accident.
- **Four verification states, not three.** `PASS` / `FAIL` / `SKIP` / `GAP`, in the injected contract. A `GAP` is a check that ran and had nothing to fail with, and it never sets the failure flag — if it did, every project without that layer would start failing a check that passed yesterday. The corollary is the point: silence must not read as clean.
- **Prose links are checked; code examples are not.** `tests/links.test.mjs` resolves every markdown link in prose across agents, skills, crafts, pipelines, commands and docs. The rule that makes it usable is `code shows, prose points` — a path inside a fence or an inline-code span is being displayed as syntax, a path in prose is being offered to follow, and only the second is a promise. Without that distinction every example tree reads as a broken link, which is how a gate earns the right to be ignored. An unterminated fence swallows the rest of the file, which a paired regex quietly declines to do.
- **The arms harness reports whether it verified its own control.** `--setting-sources project,local` was the isolation mechanism and nothing checked that it held. The scorecard now reads the control cells' transcripts and prints `clean`, `BLOCKED`, or `NOT CHECKED` on every run — never nothing. A lift measured against a control that saw the treatment is a lower bound of unknown size.
- **The README count table is asserted against the filesystem.** A README that misstates what ships is the cheapest kind of lie to tell for a dozen releases without noticing.
- **`docs/skill-doctrine.md`.** The three rules the above rests on, adapted from the rsc-harness rubric: discriminative power over coverage, length as a cost, and an honest 7 over a dishonest 9.
- **Skills reach the specialist as Level-1 pointers.** Agents declared `skills:` in frontmatter and nothing read it — the same defect class `od.craft.requires` had. `SubagentStart` now resolves it and injects name and description, never the body. Researched rather than settled by taste (`docs/context-delivery.md`): Anthropic publishes ~100 tokens per skill for Level-1 metadata against under 5k for a body, and measured here the bodies cost 4–7× to collapse two levels the host already separates. Tokens are the smaller half of the argument — unassisted the model matches a task against all 34 skills, while a specialist matches against the 1–5 its role declares, already filtered by domain. Crafts keep arriving in full: a craft always applies, a skill applies sometimes, and that is exactly the Level-1/Level-2 split.
- **Route-table pairings are now declared and gated.** The router paired `reviewer` with `design-review` and `engineer` with `systematic-debugging` in two route tables, while neither agent declared the skill — so the dispatch never carried what the table promised. Declared, along with `researcher` (`scout`, `docs-seeker`, `deep-research`, one per row of its own Routing table) and `design` (`data-visualization`). A test now asserts every agent+skill pairing in a route table is declared by that agent.
- **A vacuous gate, fixed.** The craft-requirement test parsed `requires:` blocks with a loop that broke on the empty string `split("\n")` leaves before the first item, so it read zero requirements and passed unconditionally. Mutating a declared craft to a nonexistent name now fails the suite.
- **Intensity dial (`/praxis:mode fast | full | deep`).** Praxis re-judged "trivial or substantial" on every turn, so a typo fix could cost a Run Card and an architectural change could be waved through for having a small diff. That call now belongs to the person driving. The level is held in a flag file rather than in the conversation — parsed by the `UserPromptSubmit` hook, not by a Markdown command, because a rule the model reads is followed most of the time and a file the hook reads is applied every time. It travels into dispatched specialists, and it governs ceremony only: the crafts, the ladder, and the safety carve-outs are byte-identical at every level. The contract is filtered by tag (`<!-- only:fast -->`, `<!-- only:deep -->`, `<!-- only:orchestrator-full,orchestrator-deep -->`) from the same single file.
- **`platform` agent.** CI, containers, build tooling, and test infrastructure — the systems that ship the code rather than the code itself. The orchestrator had routed to it all along without the file existing. Claims `web-testing` and `test-coverage-plan`, two skills no agent previously declared.
- **Crafts reach Cursor.** Cursor cannot carry the per-turn or per-subagent layers through hooks — `beforeSubmitPrompt` and `subagentStart` return `user_message`, which is display-only and never reaches the model; only `sessionStart` carries `additional_context`. So the crafts ship there as generated rule files (`.cursor/rules/craft-*.mdc`, glob-scoped for the visual ones, always-apply for `minimalism` and `orchestration`), built by `scripts/build-cursor-crafts.mjs` with a CI staleness gate. Adding a craft without deciding its Cursor scope fails the build rather than shipping unscoped.
- **Live smoke test.** Every hook test until now executed the script directly and read its stdout, which proves the script is correct and nothing about whether the host invokes it or consumes what it emits — a real distinction, since Cursor's `subagentStart` accepts well-formed output and shows it only to the human. `evals/smoke/live-hooks.mjs` runs one isolated headless session (~$0.06) and checks all eleven links of the chain, reading the dispatch-side ones in the subagent's own transcript rather than the parent's. Hooks gained an opt-in `PRAXIS_HOOK_TRACE`, inert unless the variable is set.
- **Per-turn and per-subagent injection.** Praxis primed only at `SessionStart`, so the method decayed as a session grew and never reached a dispatched specialist at all — subagents inherit no parent context, so every delegated "senior" ran Praxis-unaware. Two hooks close that: `UserPromptSubmit` restates a compact operating contract each turn (anti-drift), and `SubagentStart` carries it into each dispatched agent, scopeable via the `PRAXIS_SUBAGENT_MATCHER` regex (fails open on a bad regex, a missing `agent_type`, or a stalled payload). The contract lives in one file, `hooks/context/contract.md`, filtered per target: orchestrator-only sections (Run Card, delegation) are stripped for subagents, so a specialist is never told to dispatch specialists of its own.
- **CI, and the drift it immediately found.** Three zero-dependency gates (`tests/*.test.mjs`, run by `node --test` in GitHub Actions alongside the resource validator): referential integrity, hook behavior across host dialects, and load-bearing phrase invariants. Every gate is mutation-tested — a deliberate break must fail it — after the first traversal test turned out to pass vacuously. Writing them surfaced four real defects: the orchestrator routed to `platform` and `incident-responder` (neither exists), `orchestration` was missing from the AGENTS.md craft table, the Run Card `approach:` line named a nonexistent agent in two files, and the hooks' own `PLUGIN_ROOT` local shadowed Codex's host signal so every host resolved to the Codex dialect.
- **Craft resolution on dispatch.** Every agent already declared its disciplines under `od.craft.requires`, and nothing read that frontmatter — so "always-on crafts" was a claim, not a mechanism. `SubagentStart` now resolves the declaration and injects those craft bodies alongside the contract: `design` arrives with anti-slop + a11y-baseline + motion-discipline, `orchestrator` with orchestration + minimalism. An undeclared agent, a stock agent, or a missing payload still gets the contract. `agent_type` is confined to a bare filename so a host-supplied value cannot traverse out of `agents/`.
- **`hooks/lib.sh`.** Shared JSON escaping, host-dialect detection, memory recall, and contract filtering. Each hook previously hand-rolled its own escaping, so a fix in one never reached the others. Host detection also gained a Codex branch — Codex exposes `PLUGIN_ROOT`/`PLUGIN_DATA` and no `CLAUDE_PLUGIN_ROOT`, and was falling through to the flat Copilot shape, which Codex drops silently.
- **`agentic-lifecycle` skill.** A doctrinal umbrella for spec-driven, near-autonomous development (decision → verifiable contract → task files with status → auto-loop → review → done). It unifies `spec-lifecycle` (planning phases) and `autonomous-loop` (the ralph loop) and adds the eval-driven pillar plus a research base (`references/research-ai-native-lifecycle-2026.md`). Ships 5 artifact templates plus an auto-loop rulebook under `assets/` (decision record, plan, verifiable `spec.json` contract, task, progress ledger, auto-loop rulebook). Referenced by the `orchestrator` agent. Resource validator now skips `assets/` (as it already did `references/`).
### Changed

- **The routing floor is gated on English prompts only.** Every description is English; the eval prompts are deliberately bilingual. Split by language, rank-1 is **69.2% (EN)** against **23.5% (ES)** — a lexical ranker cannot cross languages, and the Spanish winners are near-random. The Spanish figure is reported and tracked, never gated: gating the blend invites stuffing Spanish keywords into English descriptions, which would raise the number and make the descriptions worse. The [activation audit](evals/2026-08-28-activation-audit.md) named this gap on 961 real transcripts before the lexical audit measured it; two orthogonal instruments now agree it is real.
- **Five descriptions gained vocabulary users actually say.** `copywriting` had no "button label" or "tooltip"; `systematic-debugging` no "flaky" or "intermittent"; `scout` no "already installed"; `prior art` was claimed by both `scout` and `deep-research` and is now assigned to one. Measured before and after with only those five changed: rank-1 EN **62.3% → 69.2%**, top-3 73.3% → 77.8%, `owner-at-1` 11.8% → 11.1%, **zero regressions**. Precision improving alongside recall is the signature of a real gap closing; keyword stuffing raises recall and costs precision.
- **Collision is measured on boundary-free descriptions.** A `NOT x (that is \`y\`)` clause names the sibling, which puts the sibling's vocabulary inside this description — so a bag-of-words ranker scored the pairs that work hardest to distinguish themselves as the most similar. `learn-prune ↔ praxis-memory` read 0.57 with the clauses and 0.32 without. The ceiling was gated against a number the doctrine inflated by design; re-based 0.62 → 0.38. Ranking still uses the full description, because that is what a real router reads.
- **The positive claim is budgeted at 250 characters**, measured with the boundary clause stripped. Adopted from the [gentle-ai](https://github.com/Gentleman-Programming/gentle-ai) skill style guide and checked before adoption rather than after: our claims already ran to a median of 169 with 96% under the ceiling. Whole-description length is deliberately *not* budgeted — 40% of it is boundary clauses, and the only instrument that can weigh them penalises them by construction.
- **`hooks/subagent-stop` records the ledger's shape** alongside the dispatch (`"tasks":"done=1 blocked=1 pending=1"`). Agent-level capture recorded that the engineer finished and discarded the one signal worth learning from — which tasks fought back. Counted, never quoted: three integers cannot carry a quote or a newline into a JSON row.

### Fixed

- **`templates/spec.md` was cited by three files and did not exist** (confirmed by `fd`, `find` and `test -f`). `tests/links.test.mjs` missed it because the citations sit in backticks and that test checks prose paths only. Written rather than de-referenced — `spec-lifecycle`'s `new` stage is defined as creating a spec from it — and covered by an explicit existence test. `validate-resources` now skips `templates/` as it already skipped `assets/` and `references/`.
- **Two scorer bugs, both one-directional predicates that read fine.** `/\bBLOCK\b/` matched the word inside "Does not block.", scoring a report that declined to block as if it had — and biasing against the exact behaviour the panel exists to produce. The routing scorer compared bare skill names against `praxis:test-coverage-plan` and reported 0/10 where the truth was 2/10. Both found by reading the table rather than the number; both guarded, both mutants verified red.

## [0.3.0] — 2026-06-27

### Added
- **Cross-platform.** Praxis now runs on **Codex, Cursor, Gemini CLI, and Copilot** in addition to Claude Code — one shared Markdown body, thin per-host adapters (the superpowers pattern). Added per-host manifests (`.codex-plugin/`, `.cursor-plugin/`), per-host hook configs (`hooks-codex.json`, `hooks-cursor.json`, a Codex-dialect `session-start-codex`, and a polyglot `run-hook.cmd` for Windows), a `GEMINI.md` bootstrap (Gemini primes via `@import`, no hook), a `.cursor/rules/praxis.mdc` always-apply fallback, and per-host action→tool maps under `skills/using-praxis/references/`. Skills speak in **actions** ("dispatch a subagent", "invoke a skill"); each host's reference resolves them to its real tools.
- Per-project memory injection works on every hooked host (Claude/Codex/Cursor/Copilot); on Gemini the memory is read via the documented path.

### Notes
- Per-host adapters are **wired; prove each with a smoke test** (vague prompt → does it prime + activate?) before trusting it on that host. Codex needs `multi_agent = true` in `~/.codex/config.toml` for subagent dispatch.

## [0.2.0] — 2026-06-26

### Added
- **Per-project learning (Layer 1).** The agent accumulates knowledge per project in `.praxis/memory/` (git-committable — teams share via git, no infra). `/praxis:learn` captures a *recurring* reusable delta (never one-offs) as a lesson or a `candidate` skill; `learn-graduate` pressure-tests a candidate before trusting it; `learn-prune` curates. The SessionStart hook injects the project's memory index every session — a **retrieval guarantee** that defeats write-only memory. Research-grounded (`hermes-agent`'s documented GEPA gate + the practitioner consensus that version-controlled Markdown beats memory tools).

### Changed
- **Dropped the build tooling.** Removed pnpm/TypeScript (`packages/`, workspace, lockfile, tsconfig, `package.json`); the resource validator is now a zero-dependency Node script.
- **AGENTS.md honesty.** Replaced the `/learn` + "Praxis MCP server" claims (which were never built) with the real per-project memory design; the cross-project/team backend is documented as a future, optional Layer 2.

## [0.1.0] — 2026-06-26

- **Autonomous loop** — `autonomous-loop` skill + `/praxis:loop` command with guardrails enforced outside the model (max-iterations, wall-clock, no-progress detection, completion-signal threshold, verifier-integrity guard).

- **Eval suite** — 5 measured fixtures proving the moat (replica fidelity, autonomous activation, from-scratch taste, vibe-coder clarify, and a live end-to-end build).
