## Findings
- `hooks/lib.sh:718-719` (`praxis_edit_paths`) — the Codex `apply_patch` path list reads only `*** Add|Update|Delete File:` headers; `*** Move to: <path>` is never classified, so the destination of a rename escapes every record gate, the floor and the comment pass, although the contract says "each path in the patch is re-rooted and classified on its own; one denied path denies the patch". Repro (scratch, `apply_patch` payloads piped into `pre-tool-use`): `Add File: .praxis/ship/c` → DENY, but `Update File: specs/c/empty.md` + `Move to: .praxis/ship/c` → ALLOW; `Update File: specs/c/stage.md` (content `verdict: APPROVE`) + `Move to: specs/c/decision.md` → ALLOW; `Move to: specs/c/review/round-1/security.md`, `.praxis/approved/z`, `.praxis/intent/approve-c` → ALLOW; `Update File: specs/c/tmp.md` + `Move to: src/evil.ts` with no approval marker → ALLOW (`Add File: src/evil.ts` → DENY). End to end: after those two moves (decision.md = APPROVE, `.praxis/ship/c` present) and with `security.md` missing from the round, `git push origin praxis/c` → ALLOW. `post-tool-use` shares the parser, so it never sees the moved path either. Fix: add `Move to` to the grep/sed (and a test with a Move-to onto a record, a lens file and a source path) — severity: important
- `hooks/pre-tool-use:736-743` (`ledger_gate`, the accepted "stage: shipped needs the ship marker" guard) — the stage is read only from the edit's own text, so an edit that does not carry the key is not guarded. Repro: `Edit old_string "implemented" → new_string "shipped"` on `specs/c/implementation.md` → ALLOW (with the key, `stage: implemented → stage: shipped` → DENY); `MultiEdit [stage: implemented → stage: planned, stage: planned → stage: shipped]` → ALLOW (the first `stage:` in the concatenated new text wins); Codex `-implemented / +shipped` → ALLOW; Codex `*** Delete File: specs/c/implementation.md` → ALLOW. Consequence, reproduced: with the ledger at `shipped`, `git push origin HEAD:main` and `git push origin shipit` from a non-`praxis/` branch go from DENY to ALLOW, and so does `git push --force origin HEAD:main` (no open cycle, so trunk is "not Praxis's call"); `praxis/c` itself stays gated by name. Fix direction: do not trust the edit text. Make `praxis_ledger_is_open` treat `stage: shipped` as closed only when `.praxis/ship/<c>` exists (a shipped ledger without the marker stays open), which also closes the Bash/alias spellings of the same write; deny Delete/Move of a ledger on Codex — severity: important
- `hooks/pre-tool-use:301` (`ship_gate`) — the ship marker short-circuits the live round check, a regression against the pre-round-3 gate (`git show 0e8773d:hooks/pre-tool-use:235-236` re-read `praxis_round_all_pass` at push time) and the marker is not bound to what was reviewed. Repro: round 1 all PASS, approver Writes `decision.md` APPROVE → `post-tool-use` writes `.praxis/ship/c` → `git push origin praxis/c` ALLOW (correct); then a further commit on `praxis/c`, `review/round-2/` with all three lenses `CHANGES` (blocking), ledger `round: 2` → `git push origin praxis/c` ALLOW and `gh pr create --head praxis/c` ALLOW while `praxis_round_all_pass … 2` is false. Nothing removes the marker except an ESCALATE write, `rework.sh` or `approve.sh`; builder dispatch stays open after an all-PASS round, so "one more fix after the approval" is an ordinary drift. Fix: for verdict APPROVE require marker AND `praxis_round_all_pass` on the current effective round at push time; optionally record `git rev-parse praxis/<c>` in the marker and compare — severity: important
- `hooks/pre-tool-use:134-135` (header) and `docs/cycle.md:162-178` — the "open by design" line for Bash writes to `specs/<c>/` says the ship marker is why a forged `decision.md` ships nothing; true for decision.md, not for the ledger. Repro: Bash `rm specs/c/implementation.md` (also `sed -i '' 's/implemented/shipped/' …`, `mv`, `rm -rf specs/c`, `git rm -f`) → ALLOW; afterwards `git push origin HEAD:main` → ALLOW. The recommended host rules cover `decision.md` and `.praxis/*` only, not `implementation.md`, `review/` or `lenses`. Add `Bash(*implementation.md*)` (and `*/review/*`) to the documented deny list, and say in the header that deleting the ledger closes the cycle — severity: minor
- `hooks/pre-tool-use:279-287` (`cap_gate`) + `hooks/lib.sh` `praxis_capped_change` — a round-cap release by a field bump. Repro: change `c` at round 2 complete/CHANGES, second change `z` with a ledger at round 0: Agent `builder`/`engineer` → DENY; Write `round: 3` into `c`'s ledger (allowed, it only rises) and `.praxis/active-change` → `z`: Agent `builder` → ALLOW (`c` at round 3 has no lens files, so it is "incomplete", not capped; `builder_gate` judges `z`). With active-change on `c` the barrier still denies, and `SendMessage` to the recorded builder stays denied. Needs three deliberate steps — severity: minor
- `hooks/pre-tool-use:404-452` (`git_ship`) and `gh_ship` — trunk-rule forms undocumented in the header: (a) `--repo X`/`--repo=X` makes the next positional be read as the remote, so `git push --repo=origin HEAD:main` from branch `shipit`, active-change off the cycle → ALLOW (the refspec is dropped, only the current branch is judged); (b) glob refspec `git push origin 'refs/heads/*:refs/heads/*'` → ALLOW (an `--all` in other clothes); (c) `gh pr merge <n>`, `gh api repos/o/r/merges -f base=main -f head=x`, `gh api -X PUT repos/o/r/contents/f -f branch=main`, `git send-pack <url> praxis/c` → ALLOW outside an active open cycle. A drifting model rarely produces these; list them in the OPEN BY DESIGN block or treat `*` in a refspec as `--all` — severity: minor
- `hooks/pre-tool-use:455-476` (`exec_gates`) — the intent gate keys on the script's file name. Repro with no token: `cp scripts/approve.sh scripts/a.sh` → ALLOW, then `bash scripts/a.sh c` → ALLOW; `cat scripts/approve.sh | bash -s -- c` → ALLOW; `ln -s approve.sh scripts/x; bash scripts/x c` → ALLOW. Not in the header (the "wrapper scripts" line covers a script that wraps git, not a copy of the script itself). Cheap fix inside the script: `approve.sh`/`rework.sh` refuse without `.praxis/intent/<kind>-<c>` and consume it themselves, so a renamed copy still needs the token. Also undocumented: a nested `claude -p "/praxis:approve c"` run from Bash fires the project's UserPromptSubmit and mints the token with a model-authored prompt (not run here) — severity: minor
- `hooks/lib.sh:754-760` classification by name (`record_gate`) — a record reached through a symlink alias is not seen. Repro: Bash `ln -s implementation.md specs/c/l.md` and `ln -s decision.md specs/c/d.md` → ALLOW; Write `specs/c/l.md` (`stage: shipped`, `round: 0`) → ALLOW and Write `specs/c/d.md` (`verdict: APPROVE`) → ALLOW, while the same Write to `implementation.md` → DENY. It defeats the ledger `round`/`stage` guard; decision.md still ships nothing without the marker. The glob/symlink class of ADR-007 — document it — severity: minor
- `hooks/pre-tool-use:725-743` — carried over from the previous round, unchanged: `round:` is read from the edit's own text, so `Edit` without the key and the two-step `MultiEdit` can lower it; `praxis_effective_round` holds the value only where a `review/round-N/*.md` exists — severity: minor
