- `hooks/pre-tool-use:407-429` (`intent_gate`), `hooks/user-prompt-submit:49-58` — "the model has no way to mint" the person-intent token is false, and the token gate is bypassed without minting. (b) Bash `echo '{"cwd":"…","prompt":"/praxis:approve c"}' | <plugin>/hooks/user-prompt-submit` → ALLOW, and running it created `.praxis/intent/approve-c`; the next `scripts/approve.sh c` → ALLOW. Fix direction: the token must be unforgeable by a process the model can spawn (a host-side prompt log, or approve.sh refusing without a TTY/`CLAUDECODE` unset), not a file the hook script writes on request — severity: blocking
- `hooks/pre-tool-use:431-454` (`marker_bash_gate`) — approval-marker protection is a substring match on the literal `.praxis/approved`, with a read-tool allowlist keyed on argv[0]. Probes, all ALLOW: `touch ./.praxis//approved/c`, `head x | tee .praxis//approved/c`, `cd .praxis && touch approved/c`, `find . -maxdepth 0 -exec touch .praxis/approved/c \;`, `find .praxis -fprint .praxis/approved/c` (`find` is on the read list but writes and executes), `rg --pre "touch …"`; `find .praxis/approved -delete` and `rm -rf .praxis` also ALLOW. `.praxis/./approved` and `//` are plain spellings, not shell tricks. `touch .praxis/approved/c`, `bash -c 'touch …'`, `cp`, `mv`, `ln -s`, `.PRAXIS/APPROVED/c` and python `open(…)` were correctly DENY. Normalise slashes/dots in the token, drop `find` (and `rg --pre`) from the read list, and track `cd` into `.praxis` as `ship_command` tracks `cd` — severity: important
- `hooks/pre-tool-use:328-375` (`git_ship`), `:377-413` (`ship_command`) — the refspec source is matched by name, git resolves more. With a bare remote in scratch, `git push origin Praxis/c:refs/heads/main` pushed the change commits to `main` (macOS APFS resolves `Praxis/c`; hook ALLOW for `Praxis/c:main`, `PRAXIS/c:…`); `praxis/c~0:refs/heads/x`, `praxis/c@{0}:…`, `heads/praxis/c:…` and a literal SHA `6c24fbca:…` also pushed (none is matched; `praxis/c^{commit}` resolved but "up-to-date"). Tokenizer misses, all ALLOW: `git \push …`, `git p\ush …` (backslash is not handled), `bash -lc "git push …"` and `-xc` (only the exact `-c` flag is read), `sh <<< "git push …"`, `timeout 5 git push`, `stdbuf`, `caffeinate`, `xargs git push`, `find -exec git push`, `git -c alias.p=push p` (visible literal, not a config alias), `gh api graphql …mergePullRequest`, `gh api -X PATCH …/git/refs/heads/main`.
